# Active-v17 pixel-grid multiview protocol

Active-v15 localized the ordinary browser errors to shape and fill, especially under crop, shadow,
and tilt. Active-v16 improved isolated shape classification but worsened the game action. This
protocol is locked before implementing or evaluating the candidate.

## Controlled change

Keep the deployed active-v12 soup checkpoint, 55,155-parameter topology, WASM implementation, and
active-v13 board head frozen. Compare the current single integer screenshot crop with a four-view
inference ensemble over four defensible integer interpretations of the fractional CSS-to-device
pixel card boundary: current, outward-rounded, inward-rounded, and nearest-edge-rounded. Every view
is area-resampled to the existing 30x21 RGB contract and passed independently through the same
checkpoint. Average the 220 learned triple scores and 144 attribute probabilities, then recompute
the strongest triple and all eight board-head features from those averages.

This is test-time pixel-grid averaging, not a learned ensemble, symbolic SET solver, extra training,
or a higher-resolution model. It persists no screenshots or tensors. The current crop must remain
bit-for-bit the first view and the repeated-frame pixel guard must continue to compare that view.

## Selection and audit

Run baseline and four-view inference on the same 512 feedback-free browser boards at root seed
`2026082701`, using the frozen fitted board head and 100% raw action coverage. Select four-view only
if it has fewer action failures and neither Has-SET nor No-SET accuracy loses more than one of 256
boards versus baseline. Otherwise retain baseline. Ties retain baseline.

Only a selected four-view candidate receives one 1,000-board feedback-free audit at root seed
`2026082799`. Promotion requires at least 98.0% overall and 97.5% for each board kind at 100% raw
coverage. Guarded accuracy is diagnostic only. If baseline wins, do not open the audit seed.
